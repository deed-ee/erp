# erp4us-messaging

Private workspace crate for the [NATS protocol](../../docs/specifications/nats-messaging.md), not a service. Depend on `erp4us-messaging.workspace = true`. Define and test the JSON schema and subject assignment first, then implement `Contract` on your own payload. See the [relay](../../services/article-delivery/src/main.rs) for runnable JetStream and heartbeat examples.

- Use `Route::subject` for an exact contract and `Route::all_scopes` only for a reviewed multi-scope subscription. Select tested `PROTOCOL_SUPPORT` and `SCHEMA_SUPPORT` requirements; do not use wildcard majors.
- Use `Connection::connect` with `ConnectOptions` for TLS, credentials and reconnect policy; `state()` exposes connectivity and `drain()` stops accepting new work from that connection. Connection state is not business readiness.
- Persist an `Envelope<T>` with a stable ID inside the local transaction. `JetStream::publish` validates and waits for the expected stream acknowledgement; mark the outbox only after success. For durable consumers, `operations()` exposes the native provisioning/pull lifecycle and `AckKind`; this is a deliberate escape hatch for broker operations, not application subject construction. Decode with subject, headers and bytes, then enforce domain authorization and write effect plus inbox before confirming. Use the native delayed NAK for transient failures.
- Async commands use the same durable flow with an explicit command contract and a stable command/inbox key. Core `subscribe`, `request` and `reply` are available for read-only query handling; validate the incoming envelope before replying. Check the native request error kind and validate the contract-specific reply body. The crate does not retry implicitly.
- For a heartbeat use `Envelope::system` and `Connection::publish`. For a config read or update follow the revision and startup reconciliation rules in the specification; the config provider is not implemented.
- A non-Rust service can use the JSON schemas and fixture directly with its native NATS client. Run `cargo test --workspace --locked`, `python tests/contracts/check.py` with its pinned dependencies and the [Compose delivery smoke](../../README.md#try-event-delivery).
