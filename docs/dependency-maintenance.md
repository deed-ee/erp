# Application dependency gates

Use the [organization maintenance checklist](https://github.com/erp4us-org/.github/blob/main/docs/dependency-maintenance.md) for monthly triage and urgent security response. Treat the Cargo workspace, UI, Python contracts, MongoDB and service image as distinct review boundaries. Preserve `Cargo.lock`, `ui/package-lock.json`, exact tool versions, image digests and full Action SHAs. Never group a MongoDB major upgrade with a routine client update: restore an old-format dump into a disposable target and prove the outbox and restart behavior.

CI checks RustSec advisories with cargo-audit, and the resolved workspace licenses, sources and bans with cargo-deny. The allowlist describes the current graph; adding a new license needs explicit review, not just a green build. Run `npm audit --audit-level=high` from `ui/` against the lockfile, including build tools. Inspect lower severity findings during monthly review. Trivy checks both built service images for high/critical vulnerabilities using current advisory data. All high/critical findings are printed. A high/critical finding with a vendor fix fails the gate; a critical finding without a fix still needs immediate human triage and a tracked mitigation, not automatic dismissal. Service binaries are also covered independently by RustSec. Triage third-party service image advisories against their exact Compose digest. Keep scanner failure visible; report GitHub alerts separately from scanner output.

The separate `Infrastructure image advisories` workflow scans the published MongoDB and NATS digests weekly, on manual request and when a PR changes that pin. Check its output before accepting a database dependency update; actionable high/critical component matches fail the job. A component match does not establish reachability or the availability of a patched upstream image. Track findings that need upstream action or a compatibility decision explicitly.

The current Bookworm runtime digest still needs the Debian PAM fix for CVE-2025-6020. The runtime Dockerfiles upgrade the four installed PAM packages together to the exact Debian security version `1.5.2-6+deb12u3`; there is no broad package upgrade or scanner exception. Once a reviewed base digest includes the fix, remove the overlay and rerun the image gates. If the pinned package version leaves the Debian mirror before then, update the version or base explicitly rather than falling back to an unpinned install.
