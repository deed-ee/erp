# UI foundation requirements

Stable UI IDs supplement the business catalog proposed in [#31](https://github.com/erp4us-org/erp4us/pull/31); its BD-003, BD-004, BD-006, BD-017, BD-018 and BD-021 remain authoritative for business scope, translation, traceability and demo policy once accepted.

| ID | Requirement and acceptance | First slice |
|---|---|---|
| <a id="ui-001"></a>UI-001 Identity | Use lowercase `erp4us`, the geometric four and subdued teal/slate. Version light/dark wordmarks, symbol, favicon, app icon, avatar and social card. For corporate sign-in, use local approved assets and retain the provider's authentication controls and flows. The Angular entry must not ask for provider credentials. | Reviewable assets; live profile publication pending. A versioned [Keycloak theme candidate](../../infrastructure/keycloak/README.md) is separate from integrated sign-in and provider image qualification ([#84](https://github.com/erp4us-org/erp4us/issues/84), [#121](https://github.com/erp4us-org/erp4us/issues/121)). |
| <a id="ui-002"></a>UI-002 Design system | Reuse semantic tokens and documented native controls in every module. Add components when a tested workflow needs them. | Tokens and initial recipes. |
| <a id="ui-003"></a>UI-003 Shell and scope | Keep landmarks, navigation, context and status consistent; switch only to verified scope and preserve edits on cancellation or rejection. Keep the global input keyboard-accessible across routes and clear incomplete requests and results when their context changes. Report only known environment/health data. | Fixed demo scope, focus management and keyboard search. The browser still has no verified organization selector. |
| <a id="ui-004"></a>UI-004 Module navigation | Render enabled, installed, permitted entries using stable, localized and versioned metadata; unimplemented routes cannot be selected. | Build-time module registration. Coordinate runtime discovery with [#3](https://github.com/erp4us-org/erp4us/issues/3). |
| <a id="ui-005"></a>UI-005 Workspace | Lead with the answer, then expose evidence and the next permitted step. Provide task-oriented access outside the module hierarchy. Keep tables and forms for comparison and detail. Show unavailable widgets without inventing tasks, approvals or KPIs. | Article lookup via global search and a direct product entry point; no AI dependency. See [#85](https://github.com/erp4us-org/erp4us/issues/85) and [#126](https://github.com/erp4us-org/erp4us/issues/126). |
| <a id="ui-006"></a>UI-006 Business lists | Share page controls and typed bounded server-side queries. Verify permission-aware filtering/sorting, cursor behavior and clear empty/error states. Never silently choose one record when an identifier is ambiguous. | Products and global search share the exact-name operation and choice of at most five scoped SKUs. Products also supports exact ID and SKU lookups. No catalog listing. |
| <a id="ui-007"></a>UI-007 Entity views | Share title, identifier, revision, forms and sections. Use service validation and preserve unsaved input on conflicts/cancelled navigation. | Register/get with a deep link and duplicate handling. Coordinate [#3](https://github.com/erp4us-org/erp4us/issues/3) and [#34](https://github.com/erp4us-org/erp4us/issues/34). |
| <a id="ui-008"></a>UI-008 Contextual panels | Register panels by trusted IDs and permissions; support keyboard opening/closing and avoid obscuring main content. | Product help panel. |
| <a id="ui-009"></a>UI-009 Accessibility | Meet WCAG 2.2 AA with automated and manual evidence; verify keyboard, focus, reflow, labels, status announcements and contrast without relying on color alone. | Automated first-slice checks; manual conformance review pending. |
| <a id="ui-010"></a>UI-010 Locale and preferences | Persist only display settings. Localize with stable keys and fallback; use locale-aware number, currency and date formatting with explicit time zones and allow future RTL. | English/German, system/light/dark, density, panel and navigation preferences; appearance settings in the header disclosure. |

For review of UI-003 and UI-005: a catalog user should find a known SKU from a keyboard without inferring which service owns it, see the exact filter and source, and open the same article via Products. A service-only workspace need not show material metrics. An unsupported question is not a zero count, and missing authorization must not reveal records or suggest a permission-restricted query. Evidence belongs in the existing browser and scoped HTTP tests, not a design image. This review does not approve a runtime registry, generic result protocol or new grants.

## Issue drafts for publication

- **Epic: Mature the erp4us UI/UX foundation** (UI-001–UI-010). Review the first shell and website together. Confirm the branded asset rollout, signed-off UX decisions and compatibility with #2, #3, #15, #31, #34 and #35. Track the next items below without reopening covered work.
- **Add bounded Product browsing to Master Data** (UI-006). Publish a scoped list API with a stable tie-breaking sort, documented filter allowlist, opaque cursor, explicit limits and tenant-isolation tests. Wire a shared grid only after the contract exists; verify next page, empty results and errors.
- **Define revision-checked Product editing and retirement** (UI-007). Agree on update and lifecycle/retirement use cases before promising physical deletion. Publish permission, revision and conflict semantics and test stale-write rejection. UI keeps edits and allows safe reconciliation without optimistic overwrite.
- **Complete the first UI accessibility review** (UI-009). Verify light/dark/compact, tab order, focus return, screen-reader validation announcements, zoom/reflow and target sizes on app and website. Keep regression baselines pinned to the browser and OS in CI.
