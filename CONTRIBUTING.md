# Contributing

Start with the [README](README.md), [roadmap](ROADMAP.md) and [architecture](docs/architecture/baseline.md). The roadmap explains why milestones are ordered; use the [GitHub milestones](https://github.com/deed-ee/erp4us/milestones) to find work and check the issue's dependencies and open pull requests before starting. [`AGENTS.md`](AGENTS.md) records the working rules and definition of done for the repository. Keep public discussion and code in English. No AI tooling is required.

Use synthetic data for bug reports and include reproduction steps, expected behavior and version.

Keep changes focused, add tests for behavior, run the checks in the README and document migration/rollback and contract impacts. Use a pull request and request review rather than pushing to the default branch. For architecture or protocol changes, follow the RFC process in [GOVERNANCE.md](GOVERNANCE.md). Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md). Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Sign off your contributions

Read the [Developer Certificate of Origin 1.1](https://developercertificate.org/). By signing off, you certify that you have the right to submit the contribution under the project's [Apache-2.0 license](LICENSE). Use `git commit -s` on each new contribution commit to add `Signed-off-by: Your Name <your-email>` to its message. Only sign for yourself. For a missing sign-off on your own latest commit, use `git commit --amend --no-edit -s`.
