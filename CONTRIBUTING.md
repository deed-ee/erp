# Contributing

Start with the [README](README.md), [roadmap](ROADMAP.md) and [architecture](docs/architecture/baseline.md). Reproduce bugs using synthetic data; open a focused issue with steps, expected behavior and version. English is the primary project language; contributions in other languages are welcome. No AI tooling is required. Clearly identify substantive AI-generated contributions where appropriate.

## Join the discussion

[GitHub Discussions](https://github.com/erp4us-org/erp4us/discussions) is the central public forum. Business users, industry experts, developers, designers and translators are welcome. Search for a similar topic before starting a new one. Use anonymized or fictional examples; never share customer records, credentials or confidential business information.

### Share industry knowledge

[Start a discussion](https://github.com/erp4us-org/erp4us/discussions/new/choose) in **Industry Knowledge** (or **General** while categories are being set up). Describe the industry, people, steps and exceptions in a business process. You do not need to know Git, write code or design a solution.

### Suggest a business requirement

[Start a discussion](https://github.com/erp4us-org/erp4us/discussions/new/choose) in **Business Requirements** (or **Ideas** while categories are being set up). Say who needs what, when, why, and how they would tell that it works. The [requirements workflow](docs/requirements/community-workflow.md) explains how maintainers review these suggestions.

## Contribute changes

Keep changes focused, add tests for behavior, run the checks in the README and document migration/rollback and contract impacts. Use a pull request and request review rather than pushing to the default branch. For architecture or protocol changes, follow the RFC process in [GOVERNANCE.md](GOVERNANCE.md). Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md). Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Sign off your contributions

Read the [Developer Certificate of Origin 1.1](https://developercertificate.org/). By signing off, you certify that you have the right to submit the contribution under the project's [Apache-2.0 license](LICENSE). Use `git commit -s` on each new contribution commit to add `Signed-off-by: Your Name <your-email>` to its message. Only sign for yourself. For a missing sign-off on your own latest commit, use `git commit --amend --no-edit -s`.
